Open questions

Surface syntax

  • How explicit should prompt identities be in ordinary code?
  • Should await, throw, yield, and return be dedicated syntax that elaborates to shift, or library syntax/macros?
  • What is the ergonomic syntax for introducing and exporting a fresh identity?

Precise types

  • What is the final type of shift in the presence of answer-type modification?
  • How are continuation multiplicity and escape represented: ordinary type constructors, modalities, annotations, or inferred metadata?
  • How do effect rows elaborate to identities/capabilities, if rows remain in the surface language?
  • How should payload types, result types, and resumption types be packaged for user-defined operations?

Scope and lifetime

  • Can a continuation outlive its reset? Under what ownership/cancellation discipline?
  • What does cancellation mean for a captured async continuation?
  • What must be forbidden when a prompt identity is existential and intended to stay local?

Multi-shot behavior

  • Are multi-shot continuations a core feature, an explicit opt-in capability, or a library-level abstraction over copied state?
  • How does multi-shot interact with linear resources, foreign calls, mutation, and ownership?

Handler semantics

  • Does the handler run inside or outside the delimiter by default?
  • How are nested handlers and re-entrant resumptions specified?
  • How should errors thrown by a handler itself be routed?
