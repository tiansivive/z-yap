Possible improvements and future work

1. Formal core calculus

Specify prompts, existential prompt generation, capture, resumption, and matching delimiters in a compact core. State preservation/progress properties for named and hidden identities separately.

2. Typed continuation capabilities

Give continuations explicit multiplicity and escape information. A useful target is a distinction between one-shot, affine, and multi-shot resumptions, with ownership constraints on what may be captured.

3. Effect rows as elaboration

Offer ergonomic row syntax without making it fundamental. Elaborate rows into control capabilities/identities and preserve source-level explanations in IDE tooling.

4. Structured concurrency

Build async, await, spawn, cancellation, task groups, and failure propagation on top of the same control machinery, but define lifetime and ownership explicitly.

5. Optimizing lowerings

Add escape analysis, continuation-use analysis, and lowering to CFG/state machines for one-shot local continuations. Make the compiler explain why a continuation was heap-allocated when it cannot use the cheap path.

6. User-defined control abstractions

Provide a library-level way to define operations with payloads and resumptions, then generate surface syntax and diagnostics. Effects become extensible without kernel changes.

7. Debugger support

Expose prompt boundaries, captured continuation frames, resumption counts, and scheduler ownership in source-level debugging.

8. Conservative first implementation

Implement simple semantics first. Reject or allocate conservatively. Use fuel caps for difficult checker paths. Add stronger analyses once real programs show where precision matters.
