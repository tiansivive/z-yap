Lowering and runtime

Continuation properties that matter

PropertyCompiler consequence
Used exactly onceCan often use a linear state transition rather than heap-allocate a general continuation.
Does not escape the handler/reset scopeCandidate for stack/CFG/state-machine lowering.
Used zero or one timeMay support affine representations and cancellation-like branches.
Used more than onceNeeds multi-shot semantics: copyable snapshots, replayable frames, or an explicitly persistent representation.
EscapesNeeds a reified continuation object or closure-like state with a lifetime/ownership story.

Cheap lowering target

For a single-shot non-escaping continuation, shift/reset can lower to a control-flow graph or state machine. The continuation is a known successor block plus captured locals. This is the performance target for common constructs such as early exit, direct-style local awaits, and structured backcalls.

Escaping and multi-shot lowering

Once continuation state must survive independently of the current frame, the compiler needs an object, closure, coroutine frame, or equivalent runtime representation. Multi-shot capture adds a further requirement: state must be copied, persistent, or replayable. The language should not pretend these have the same cost.

Where modalities fit

Multiplicity, ownership, escape, and lowering strategy can be dimensions/modality information rather than ad hoc special cases. The control identity says which boundary. Multiplicity and escape say what representation is legal and cheap.

V1 implementation stance

  • Start with explicit prompt identities and a conservative continuation representation.
  • Track enough information to reject clearly invalid uses.
  • Use a fuel/iteration cap where the typechecker needs a pragmatic termination bound.
  • Add stronger productivity, escape, and multiplicity analysis later.
  • Optimize only proven single-shot, non-escaping cases first.
