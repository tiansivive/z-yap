Typing and effect lifting without a built-in effect system

The question

How can an effect become visible to types if the core language does not contain a privileged effect system?

Answer

The control identity is an ordinary typed entity, or an ordinary type-level marker, carried by the constructs that need it. The core needs primitives for delimited capture and binding, but it does not need a closed built-in catalogue of effects.

Control ε
reset : Control ε -> A -> A
shift : Control ε -> ((A -> B) -> B) -> A

This is schematic rather than final surface syntax. The essential point is that ε is a parameter. Async, exception, retry, generator-yield, and local early exit can each choose distinct identities and payload/resumption types.

What gets “lifted”

Not a monolithic Effect base class. A function may quantify over or require a particular control capability:

fetchAndDecode :
  using Control Async
  -> Request
  -> Response

Or it may hide the identity:

withLocalAbort : (Unit -> A) -> A
// internally introduces ∃ε and never exposes it

The exact syntax can vary. The important distinction is whether callers can observe and supply the identity.

Why existential identities matter

Without existentials, every local use needs a globally named effect or a universal top effect. That pollutes signatures and encourages accidental cross-handling. With a fresh hidden identity, a local abstraction can use shift/reset internally while presenting an ordinary interface precisely because no continuation/control capability can escape.

Relation to rows

Effect rows remain useful as a presentation and composition layer:

f : A -> B ! { Async, Throw ParseError }

But they need not be primitive. A row can elaborate to required control identities/capabilities. This keeps the core smaller and leaves room for user-defined modalities or effect encodings. The report does not assume this elaboration is already fully specified.

Matching boundaries

reset [Throw ParseError] {
  reset [Async] {
    ...
  }
}

A parse-error shift cannot be consumed by the async reset merely because both are effects.
