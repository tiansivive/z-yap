Core model

Effect identities are prompts

An effect identity ε is a delimiter target. It may be explicit and nameable, or fresh and existentially hidden.

reset [ε] { body }        // install/bind delimiter ε
shift [ε] (k => handler)  // capture up to nearest matching reset ε

The nearest reset with the same identity handles the shift. A reset for ε₁ does not catch a shift for ε₂. Nested independent control domains therefore compose without pretending that exceptions, async, and logging are one undifferentiated effect.

Named and existential forms

Named effect identity

reset [Async] {
  let x = await task
  x + 1
}

Async is available for typing, documentation, matching, export, and compilation strategy selection.

Existential effect identity

reset {
  let x = localEarlyExit(...)
  x + 1
}

This is conceptually:

pack ε in reset [ε] { ... shift [ε] ... }

The identity cannot escape accidentally because callers cannot name it. The whole construction is locally delimited.

Exporting a bound identity

A reset can intentionally expose an identity or handler capability for later use. Downstream code can consume it through explicit environment passing such as using. The exported thing remains explicit in the program’s type-level or implicit environment; it is not silently transformed into ambient global state.

What “handled” means

Handling a shift means choosing what to do with the captured continuation. It does not necessarily mean that all obligations vanish. A handler that resumes immediately may locally discharge the operation. A handler that stores k, returns it, or schedules it for later exports the control capability in another form.

Invariant: a retained or forwarded continuation carries the relevant resumption/control obligation. A type rule that erases the effect while permitting the continuation to escape is lying.
