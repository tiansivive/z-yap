Shift / reset with existential effects

This is the consolidated design for typed control effects in Yap. It starts from shift/reset, not from a privileged built-in effect system.

Final shape

Control effects are identified by prompt/effect identities.
A named identity is visible to types and can be handled deliberately. An unnamed identity is fresh and existentially hidden. reset binds or installs an identity; shift targets one. Only a matching reset handles that shift.
reset [ε] {
  ...
  shift [ε] (k => ...)
  ...
}

The default form is existential:

reset {
  ...
  shift (k => ...)
}

Conceptually, the latter creates a fresh ∃ε. Outside that reset, code cannot name or accidentally handle it. This permits ordinary local control without introducing a global AnyEffect, a top effect, or a subtyping hierarchy.

What this design is for

  • Delimited continuations.
  • Exceptions, early exits, backtracking, coroutines, async/await, and custom control abstractions.
  • Precise typing where the program chooses to expose the effect identity.
  • Convenient untyped/local control where the identity should remain private.
  • Compilation decisions based on continuation multiplicity and escape.

Non-goals

  • No mandatory global effect algebra.
  • No built-in hierarchy such as Async <: Effect.
  • No claim that all handlers erase all effects.
  • No requirement that the first implementation solve every productivity, linearity, or optimization problem perfectly.
