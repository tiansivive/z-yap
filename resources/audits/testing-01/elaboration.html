Elaboration Cleanup Plan

Highest-leverage cleanup area: elaboration is close to the language semantics, is stabilizing, and has many tests that can gain direct assertions while keeping snapshots for regression.

Overview Pipeline View Feature View Snapshots Elaboration Actions

Default Pattern

The goal is to keep regression snapshots while adding direct claims about type, term, constraints, and shape. 

const { displays, structure } = elaborateFrom(src);

expect(displays.type).toContain("Num");
expect(displays.term).toContain("FFI.$add");
expect(displays.constraints).toContain("Num ~~ ?1");
expect(structure.term.type).toBe("App");

expect({ displays, structure }).toMatchSnapshot();

Priority Targets

Target Current Problem Semantic Assertions To Add
match.test.ts Broad snapshot-only coverage. Branch result type, pattern binder presence, join constraints, mismatch as explicit failure or explicit unsolved constraint behavior.
let-polymorphism.test.ts Many combinator snapshots with little direct signal. Generalized type shape, use at multiple concrete types, monomorphism negative, recursive case expectation.
variants, tagged, injection Thin positives and few negatives. Tag/payload type, row/variant shape, unknown tag or wrong payload negative.
tuples, lists, dictionaries Small snapshot-heavy tests. Schema/indexed type shape, element constraints, heterogenous list negative, value-level dictionary if supported.
annotations, holes, modal Positive-only or skipped coverage. Bad annotation negative, hole meta/context behavior, modal/refinement preservation boundaries.
shift-reset Some module-level tests are pretty-snapshot heavy. Bubble count, Bubble meta/resumption relationship, dependent continuation resolved type, wrong resume type as explicit failure.

Good Existing Pattern

structs.test.ts is the model to spread: regex helpers like Field.bare, Field.modal, and Liquid.mentions make semantic assertions readable while snapshots still catch broader regressions.
