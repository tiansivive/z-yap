GRAM And Active Pipeline Notes

GRAM tests should be judged differently from core elaboration. The graph infrastructure and many passes are well tested, but parts of lowering are behind because the current GRS layer cannot express aggregate joins such as "collect all captures" as first-class graph patterns. The codebase notes LoGRAM as the planned Datalog/triple-store layer for those cases.

GRAM/bridge errors in integration snapshots should be split from core language claims. A record, pattern, or higher-order program can have correct parser/elaboration semantics while still exposing active-pipeline lag. Tests should say which layer they are protecting.
