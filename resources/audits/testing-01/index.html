Testing philosophy: snapshots remain useful regression artifacts. As core elaboration, normalization, and language semantics stabilize, tests should pair snapshots with direct semantic expectations so each test states the behavior it protects.

Main Verdict

The suite has real semantic coverage, especially in solver internals, GRAM graph passes, struct/dependent-field inference, normalization core evaluation, unification, and focused shift/reset tests. The main weakness is that many tests still rely on snapshots as the primary assertion.

The highest-value cleanup is an assertion pass: add string/regex/shape/verdict expectations that state the semantic claim, preserve snapshots where they help catch collateral regressions, and audit snapshots that currently bless known errors.

Top Findings

  • Elaboration should be the first cleanup target. It is central, stabilizing, and many tests can be strengthened with displayed-type, displayed-term, constraint, and structure-shape expectations.
  • Integration snapshots contain known errors. Some are expected invalid programs, but many are known implementation bugs or downstream GRAM/bridge lag.
  • Parser coverage is migration context. Nearley gaps are useful to know, but the main payoff is carrying them into the tree-sitter test plan.
  • Verification has strong solver tests but inconsistent integration verdict assertions. Refinement integration tests should assert verdicts directly.
  • Shift/reset has meaningful focused coverage. Remaining gaps are nested delimiters, resume-without-shift, dependent continuation runtime, and active bridge/runtime parity.
