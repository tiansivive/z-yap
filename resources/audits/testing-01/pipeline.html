Per-Layer Detail

Integration
  • Good: broad language-tour coverage and strong refinement examples.
  • Needs work: most non-refinement tests need direct assertions and error classification.
  • Issue: snapshots mix elaboration, verification, GRAM, MIR, and backend output, so downstream lag can obscure successful core semantic tests.
Parser
  • Good: processed AST snapshots are valuable as a migration baseline for expected syntax shapes.
  • Needs work: carry missing syntax and negative cases into the tree-sitter test plan rather than expanding the Nearley suite substantially.
Elaboration / Inference
  • Good: struct/dependent-field tests show the desired style: semantic regex helpers plus snapshots.
  • Needs work: broad snapshot-only suites should gain semantic string/regex/shape expectations.
Normalization / Unification / Pretty
  • Good: direct normalized-value assertions and unification negative tests are strong.
  • Needs work: pretty tests are format-only snapshots; generalization snapshots need semantic review; missing occurs/stuck-neutral edges.
Verification / SMT
  • Good: solver internals and validity-vs-SAT unit tests are strong.
  • Needs work: refinement integration tests should assert verdicts directly, then snapshot as regression evidence.
  • Note: usage semantics are future verification work; current tests should avoid implying usage/resource properties are checked today.
GRAM
  • Good: graph and pass tests use tag/edge queries and are not just display snapshots.
  • Needs work: active bridge parity, compile failure tests, type-level/implicit translate nodes, and LoGRAM-related backlog visibility.
