Language Feature View

Vertical-slice view of user-facing Yap features. A feature is well covered when the relevant layers agree: syntax shape where applicable, elaboration/type semantics, normalization or verification behavior where applicable, and GRAM/runtime behavior when the feature is expected to execute.

Overview Pipeline View Feature View Snapshots Elaboration Actions

Shift/Reset

Parser syntax, elaboration Bubble/meta semantics, normalization under delimiters, GRAM resumption graph, and active bridge/runtime behavior are separate claims.

Refinements

Parser/elaboration should preserve refinements; verification should assert validity/invalidity; usage semantics remain future work and should not be implied.

Records

Record syntax, dependent fields, row polymorphism, pattern matching, and bridge/runtime pattern dispatch need different tests even though they are one feature family.

Feature Matrix

Feature Status Missing Or Weak Tests
Primitives/literals Covered, duplicated Use parser gaps as a tree-sitter migration baseline: floats, false, string escapes, negative numeric syntax. Collapse arbitrary literal duplicates into table cases elsewhere.
Functions/application Good core Active full-pipeline runtime for curried closures is still behind; integration should assert elaboration success separately.

Variants/pattern matching Parser and GRAM good, elaboration assertions weak Invalid tags, bad payloads, branch joins, list/wildcard parser patterns for tree-sitter, bridge behavior split from elaboration semantics.
First-class types/dependent types Broad positives Invalid type annotation RHS, type-level match failure, dependent field reference errors, generic dependent pair direct assertions.
Polymorphism/implicits/typeclass pattern Many examples, weak direct claims using parser/inference, ambiguity, unresolved implicit remains abstract, explicit @ override edges, module-boundary behavior.
Row polymorphism Relatively strong Row literal integration, open/closed record negative pairs, extension preserving extra fields.
Refinements/verification Strongest integration area Every refinement integration case needs direct verdict expectations; add variance, refinement-polymorphism, higher-order, false-branch, nonlinear, and unknown cases.
Shift/reset/resume Implemented and tested in focused layers Nested reset delimiters, resume-without-shift, dependent continuation runtime, active graph/runtime parity, interaction with blocks/refinements.
Modules/import/export Rudimentary and under-tested Tree-sitter parser and integration coverage for export *, import "...", and module-boundary implicit behavior.
