Policy

Policy: most existing snapshots should stay during cleanup, but tests should not rely on snapshots alone for correctness. A test should say what it means directly, then snapshot the broader output for regression detection.
Layer Direct Semantic Assertion Snapshot Role
Elaboration / Inference displays.type, displays.term, displays.constraints, regex helpers, structure.term.type. Keep displays snapshots for regressions. Use full structure snapshots sparingly.
Integration Expected type, normalized value, validity, and expected/no expected error per declaration. Keep full-pipeline snapshots when they are useful archaeology; split core vs debug output later.
Parser Unambiguous parse plus discriminant/shape assertions for key syntax. Keep AST snapshots as migration references for tree-sitter where syntax shape is the contract.
Normalization nf.type and NF.display(...) exact values or neutral shape. Keep snapshots only for complex neutral/Bubble displays.
Verification valid, invalid, unknown, raw SAT/UNSAT only in solver tests. Keep solver trace snapshots in trace tests; integration traces should be supporting evidence.
GRAM Graph tag counts, edge queries, pass invariants, runtime result for bridge. Keep graph snapshots when paired with queries.

Error Inventory

A direct scan of snapshot files found embedded errors in integration snapshots, plus expected unification failure snapshots. Each error should have an explicit testing role.

Error Class Examples Found Meaning Action
Expected semantic failure Cannot unify in unification error snapshots. The test intentionally verifies a failure contract. Keep, but pair with explicit error-type/message assertions when missing.
Known implementation bug Unbound label: width, Expected number, got wildcard, Variable not found: fact. The tour says these features should work or are becoming expected to work. Do not preserve as passing regression output. Fix, or mark as explicit known limitation until fixed.
Downstream GRAM/bridge lag Bridge: struct pattern dispatch not yet implemented, Bridge: closure capture not yet implemented for curried returns. Elaboration may be correct while active graph/lowering is behind. Split the claim: assert elaboration semantics now; track active bridge parity separately.
Backend lag/noise emit_erl: unknown function arity for "unknown". A backend-specific limitation is leaking into broad language-tour snapshots. Keep only in backend-targeted tests; integration should not silently bless it unless the test is about backend lag.
Unexpected runtime exception Cannot read properties of undefined (reading 'type'), Unbound bound variable in synth. Likely real bug or unclassified implementation failure. Prioritize triage. These should not remain generic golden output.
