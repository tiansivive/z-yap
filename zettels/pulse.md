# Pulse — current narrative

Editorial snapshot of where the actively-tracked work in z-yap stands. One paragraph per thread, updated at the end of sessions that materially move a thread forward. This is the curated companion to the auto-generated views in `scripts/current-state.js` and `scripts/status.js`.

Coverage here is only the work tracked through z-yap threads. For features of Yap that pre-date z-yap tracking, see [[yap-baseline]].

## Delimited Continuations

The core vertical is implemented and exercised: surface `shift`/`reset`/`resume` elaborate through answer-type polymorphism ([[answer-type-polymorphism]]), continuation binders ([[continuation-binders]]), and multishot replay at let-boundaries ([[nondeterminism]], [[nondeterminism-multishot]]), with NbE evaluation over an explicit work stack ([[shift-reset]]). Lowering is direct-style (D-004, [[direct-style-lowering.adr]]): an `Alloc`/`Read`/`Jump`/`Branch` block state machine with no CPS translation and no first-class continuation value. Per D-006 ([[gram-canonical-ir.adr]]) the canonical lowering site is now `src/GRAM/bridge/continuations.ts` ([[shift-reset-bridge-lowering]], multishot at [[multishot-bridge-serialization]]); the move from `src/lowering/continuations/` was a site move, not a shape change, and the legacy MIR zettels [[shift-reset-mir-lowering]] / [[multishot-serialization]] are deprecated. The active design front is verification: today shift/reset is a pass-through stub ([[shift-reset-verification-stub]]) treating `Reset` as transparent and `Shift` as opaque `NF.Any`; real VC generation ([[shift-reset-verification]]) is blocked on the `Bubble` EB.Term representation ([[bubble-semantics]]), whose Phase 1 has landed ([[bubble-semantics-phase1.implementation]]), leaving Phase 2 verification and the [[tell-listen-resumption-refactor]] cleanup as the next concrete steps. Further out and design-only: a written typing calculus ([[missing-spec-shift-reset]]), single-shot static specialisation gated on QTT usage ([[singleshot-static-specialization]]), and the speculative nondeterminism-as-effect line ([[choose-fail-effect]], [[nondet-handler]], [[fair-nondet-scheduling]]) grounded in [[filinski-representation-theorem]]. Selective CPS ([[selective-cps]]) is the rejected alternative.

## Elaboration V2

The generator-based pipeline is the live elaboration path: inference dispatches from `elaborate.ts` via `ts-pattern` into per-construct handlers, checking runs in `check.ts`, and both thread effects through the [[elaboration-monad]] — a single `Elaboration<A>` over reader (`EB.Context`), a writer-shaped collector (constraints, binders, metas, per-term types, composed zonker), and mutable state, driven by the `V2.Do` [[generator-monad]]. V1 is the deprecated fp-ts-centric *API style*, not a parallel infer tree ([[v1-elaboration-pipeline]]); the "inference.v2/checking.v2 + tmp.ts stubs" migration framing is historical — no such directories or stubs exist in the tree, and the cores already run on V2. The remaining seam is the module driver `module.ts`, still sequencing statements with fp-ts `Either`/`pipe`; the most recent material change was a zonker-propagation fix there ([[module-zonker-fix]]) where `expression` dropped the told zonker, losing let-generalization substitutions. Two design gaps are explicitly deferred pending a written calculus: let-polymorphism ([[missing-spec-let-polymorphism]]) and dependent Sigma records ([[missing-spec-sigma-types]]), the latter still needing the nested-sigma label environment to become a proper stack. Generalization now yields the principal type for unconstrained pattern binders — collecting kind annotations transitively so an unknown binder kind becomes its own `Π(_: Type)` binder rather than leaking a meta or defaulting to `Any`; the residual `Any` default at instantiation is an open design question ([[instantiate-any-default]]). Nested dependent structs now solve: an interim meta-threading patch in row unification ([[solver-meta-threading]]) keeps solve-minted metas visible to kind lookups, pending the [[monad-split]] refactor that retires it. The generalization collector now resolves metas through the zonker in row-tail positions too ([[meta-collection-zonker]]), closing a residual let-poly escape where an already-generalized row meta was re-quantified onto an enclosing block. Near-term work is test hardening, not new mechanism: match/let-poly/variants/tuples/holes/dictionaries/modal suites are snapshot-only and need direct semantic assertions to count as correctness contracts ([[test-coverage-gaps]]).

## Explorer Audit

A systematic pass ran all 19 explorer snippets through the full pipeline (parse → elaborate → type → NF → IVL → solver trace → GRAM → MIR → codegen), surfacing crashes, undeclared MIR variables, wrong types, and semantic codegen errors. The thread is archived: most findings landed as fixes spanning NF quoting ([[stuck-quoting-fix]]), bridge type-level erasure and label resolution ([[bridge-type-erasure]], [[bridge-label-resolution]]), pattern row binders ([[pattern-row-binder-fix]]), implicit Pi wrapping ([[wraplambda-fix]]), module zonker propagation ([[module-zonker-fix]]), closure capture for curried returns ([[bridge-closure-capture]]), and two verification gaps ([[verification-unconstrained-meta]], [[verification-rigid-mismatch]]); four snippets were corrected surface-syntax errors, not compiler bugs ([[explorer-snippet-syntax-fixes]]). The audit forced one language-level decision — unconstrained implicits generalize rather than defaulting to `Type` ([[implicit-generalization-semantics]]). One finding remains open as design work on [[pipeline-stabilization.thread]]: struct `match` emits a variant-style empty-string tag test instead of field projection and dispatch ([[bridge-struct-dispatch]]). A later re-scan confirmed three still-open backend codegen bugs — match join-block scoping, positional-field access, and a residual type-leak — recorded together ([[codegen-correctness-gaps]]). The IVL and Trace tabs that instrumented the audit are stable; forward tooling is tracked under [[explorer-evolution.thread]].

## GRAM Evolution

GRAM is the canonical compilation IR: per D-006 ([[gram-canonical-ir.adr]]) all compilation flows `EB.Term → GRAM → MIR → codegen`, with `GRAM.Bridge.emit` the sole MIR source for explorer, REPL, and file-compile, and direct `lowerToMir` deprecated with no production callers. The substrate ([[gram]], D-002) and its static pipeline are complete and tested — `translate` plus `resolve-labels`, `eta`, `saturate`, `shiftReset`, `pattern`, `label-cycles`, `closure`, `knot`, refined by the DPO engine. Record values now translate to a flat [[gram-struct-node]] (labeled `:field` edges) rather than the row cons-list, with `:label` references resolved to graph edges ([[gram-label-resolution-pass]]) and record-capturing fields tied by the [[recursive-struct-binding]] knot. The [[gram-to-mir-bridge]] emits MIR mechanically; the remaining gap is struct match dispatch ([[bridge-struct-dispatch]]). Programmable GRAM passes ([[programmable-gram-passes]]) shipped an MVP (phases 1–6): user DPO rules carried as a `gram` modal annotation, discovered and topologically ordered by the implemented [[gram-kernel-pass]]. That work is implemented-but-incomplete — the retrospective ([[programmable-gram-passes-mvp-retrospective]]) surfaced four follow-ups, of which [[gram-string-escaping.bug]] and [[gram-rule-scoping.design]] BLOCK completion and phase 7 is deferred behind them. The [[gram-pap-pass]] is a shipped builtin resolving unsaturated externals into PAP nodes upstream of the bridge; [[bridge-closure-capture]] resolved curried-return bundle emission on the bridge side. Next step is the static-pass roadmap in [[gram-next-steps]] — defunctionalization, lambda lifting, phased CRUD enrichment ([[gram-crud-enrichment]]) — alongside the two blockers; v2 payload-predicate features ([[pap-analysis-payload-predicates]]) remain needs-design. LoGRAM, the GRAM interpreter, and self-hosted passes are speculative.

## Parser Migration

The shipping parse path is Nearley: `grammar.ne` compiles to tables, postprocessors build `Src.Term` with source spans ([[nearley-parser]], [[parser-processors]]), and this is what [[elaboration]] ingests today. The tree-sitter target ([[tree-sitter-parser]]) — incremental, error-recovering, intended to supersede the ambiguous CFG and back [[lsp]] — lives in an external `tree-sitter-yap` package with no presence in this repo yet: the generated typings, CST helpers (`extractFields`/`extractParam`), `ts-dts` script, and tree-sitter dependency are all absent. Two coverage gaps shape the migration: within Nearley, `grammar.ne` references `P.Mu` for μ-recursive types but `processors.ts` defines no `Mu` processor (a confirmed grammar↔processor drift); and the module grammar produces only basic export/import/script, not the qualified/hiding forms anticipated. The [[surface-syntax-backlog]] and [[testing-audit-2026-06-20]] parser findings inform expectations but are not active commitments. Next step is to land the tree-sitter CST surface in-repo — wire `ts-dts`, generate typings, expose CST through the barrel — before any dual-backend cutover, while closing the `Mu` processor gap on the Nearley side.

## Pattern Matching

The compilation backbone is implemented end to end: surface `match` elaborates each arm into context binders and unifies result types, then lowers via Maranget clause-matrix decision trees ([[pattern-algorithm-choice]]) in two settings — MIR block emission ([[pattern-matching-compilation]]) and a two-phase GRAM path translating `EB.Pattern` into `pat:*` graph nodes then building the tree as an aggregate pass ([[gram-pattern-translation]], [[gram-pattern-pass]]). Variant, literal, struct, binder, and wildcard columns are covered; list patterns are a natural extension still to be wired. The active frontier is elaboration-time safety: [[exhaustiveness-checking]] and redundancy diagnostics are unimplemented and needs-design — lowering only emits a runtime fallback — and the design hinges on open-vs-closed variant semantics ([[design-open-closed-variant-semantics]]), shared with Row Types. A concrete case sharpens the redundancy half ([[redundant-match-arms]]): an irrefutable arm shadows every later arm, and because scrutinee inference stays faithful — keeping each arm's field requirements without pruning by reachability — the remedy is a redundancy diagnostic, and making an earlier arm refutable promotes a shadowed arm to live with no change to callers' types. Dependent matching is partially live (checked match with polymorphic return type works after the recent de Bruijn alignment fix); branch-local equality assumptions for stuck dependent types remain a design item ([[dependent-match-implication-constraints]]). The most recent shift is conceptual: [[functional-patterns]] was rewritten to separate Curry-style inversion from forward [[view-patterns]], spawning [[narrowing-vs-residuation]] and [[two-tier-pattern-compilation]] (constructor tier on Maranget, functional-pattern tier on the shift/reset substrate); these, with view/synonym/active patterns and with-abstraction, remain speculative. Next step: surface exhaustiveness/redundancy checking, gated on the open/closed decision.

## Pipeline Stabilization

This thread tracks bugs surfaced when [[language-tour]]'s integration test gave end-to-end visibility across all passes — issues invisible while each pass was tested in isolation. Frontend and middle-end fixes have largely landed: `$eq` normalization ([[eq-normalization-bug]]), let-poly implicit escape ([[letpoly-implicit-escape]], [[module-zonker-fix]], [[fst-closure-annotation]]), `mapList` schema unification ([[maplist-schema-unification]]), the `length` recursive de Bruijn bug ([[length-recursive-debruijn]]), and both Sigma-quoting bugs ([[sigma-quoting-match]], [[sigma-quoting-field-ref]]). The GRAM→MIR bridge is now mechanical for the major value-shape gaps: unsaturated externals lower through [[gram-pap-pass]] → explicit PAP nodes ([[bridge-unsaturated-external]]), curried-return closure capture uses the shared bundle ABI ([[bridge-closure-capture]]), records lower through flat [[gram-struct-node]] `:field` edges, and labels captured into closures read off the captured record through resolved `:refers_to` edges ([[gram-label-resolution-pass]], [[recursive-struct-binding]], [[bridge-forward-label-refs]], [[bridge-label-closure-gap]]; merged PR #9). The latest fix gives variants a real `{ __tag, payload }` runtime discriminant and makes struct-match switches follow their `:inspect` edge into projection/sub-pattern branches, closing [[bridge-struct-dispatch]] across GRAM, MIR, codegen, and verification. A narrower [[string-dispatch-float-record-bug]] remains for literal/general dispatch stringification, while the main stabilization frontier is type erasure: `Leaf.erase()` strips type-only shapes at the MIR boundary, but principled cross-backend erasure of `∀`, proofs, and refinement witnesses is open and tied to QTT ([[type-erasure]]). The GRAM→MIR merge now threads each match arm's result through a join-block parameter ([[match-merge-block-params]]) instead of a case-block-local variable, keeping the join read in scope and resolving the codegen match join-block scoping symptom ([[codegen-correctness-gaps]], now down to two genuine backend gaps). The `:label` pipeline gaps from PR #9 are closed (PR #14): self-referencing struct fields check under record-type annotations ([[checking-path-label-unbound]]), and a `:label` inside a refinement translates to a VC by re-establishing the sibling-label scope at every record boundary ([[ivl-label-translation]], [[verification-label-scope]]). Next step is the type-erasure design/implementation pass.

## Recursion

Equirecursive μ types are the implemented core: μ binders share the `Abs` node (discriminated by `binding.type === "Mu"`), recursive lets wrap their inferred type in a μ, and μ-heads stay neutral during NbE so normalization never unfolds infinitely ([[mu-types]]). Equality is decided by unfold-and-recurse in the unifier, with `unfoldMu` recording steps to break loops ([[mu-type-unification]]). Mutual recursion works within a row/struct via Sigma + label variables and across top-level lets through sequential context growth; cyclic top-level groups would need SCC/backpatching ([[mutual-recursion]]). The standing gap is occurs-check recovery: a cyclic meta solution throws rather than constructing a μ, and decidability rests on a step budget, not a termination proof ([[equirecursive-types]]). Everything beyond is design backlog: a written μ calculus ([[missing-spec-recursive-types]]); bisimulation-based equality ([[design-bisimulation-equality]]); and coinductivity, ν types, productivity/sized types, and guardedness, all speculative. The most recent movement is at the GRAM lowering layer: value-level self-reference through struct fields now lowers via the capture-the-record knot ([[recursive-struct-binding]], [[gram-struct-node]]), with a lowering-time guardedness gate ([[label-cycle-guardedness]]) admitting lambda-guarded self- and mutual recursion and rejecting eager cycles — the codata/ill-founded boundary, and now the point where whether coinduction lives in the type system (a `ν` binder) or as a GRAM productivity check becomes a registered decision. This sharpens the sigma/codata analysis: `:label` conflates sigma (parametric, type-level, deferred) with codata self-reference (eager, value-level fixed point) ([[sigma-vs-codata-label-refs]], [[codata-vs-coinductive-types]]). The framed next step is settling whether to split the surface sigil and give value-level self-reference a ν-binder core versus keeping context-driven dispatch ([[design-sigma-codata-label-refs]]); codata records are the near-term need, full coinductive theory the deferred commitment. Loop sugar remains deferred ([[loop-sugar]]).

## Row Types

`R.Row` is the realized universal substrate for compound data: structs and tuples share one inference path, variant literals build tagged-arm rows, injection/projection rewrite row spines ([[rows-universal-substrate]]). Row unification ([[row-unification]], flex/rigid variables with scoped-label rotation per Leijen) and row polymorphism ([[row-polymorphism]]) are implemented and drive records, tuples, variants, tagged values, and label lookup, with lists/dictionaries kept as deliberate non-row FFI containers. The most recent fix corrected sigma checking of struct values to infer-then-recheck so singleton field types fire ([[sigma-checking-infer-constrain]]), and self-referencing struct fields now check under record-type annotations — the `[struct, Sigma]` re-check threads inferred field values into `ctx.sigma` and constrains each label to its declared type ([[checking-path-label-unbound]], PR #14). The open frontier is design, not core mechanism. Verification-side row reasoning is the active blocker, shared with [[verification-backend.thread]] as Milestone 4 ([[milestone-4-rows]]): IVL carries a row sort and Empty/Extend/Var algebra, but `translate.ts` throws on concrete row literals, so the gap is emitting row VC nodes plus a structural containment theory aligned to label-based semantics ([[row-theory]], [[design-row-theory-verification]]). Remaining language-side items: open-vs-closed variant semantics ([[design-open-closed-variant-semantics]]), data-declaration sugar ([[data-declarations]]), and the speculative customizable-data-types / indexing space ([[customizable-data-types]]). A scoped internal refactor for dedicated EB.Term row constructors ([[dedicated-row-constructors]]) is planned but unscheduled. Next step: the verification row theory.

## Testing

The suite is snapshot-driven Vitest across every pipeline stage with deterministic ID resets ([[snapshot-testing]]), CI enforcing lint, formatting, dead-code, type-check, and coverage per PR. The gates went genuinely green under [[lint-governance]]: ESLint debt is baselined-and-ratcheting in `eslint-suppressions.json`, knip runs advisory pending its orphan cleanup, and one `tsconfig.json` now covers src and tests, so `pnpm typecheck` verifies test files too (the five stale-API test files that had drifted are fixed). Mature layers — solver theory plugins, GRAM passes, struct/dependent-field inference, NbE, unification — are stable; [[v1-test-cleanup]] retired the defunct v1-monad test files, porting eight pattern-matching cases into the active v2 suites. Current work is methodological: the [[testing-audit-2026-06-20]] reframes "skipped tests" as one signal among several and drives two in-flight efforts — [[semantic-assertions-with-regression-snapshots]] (pair every snapshot with a direct claim so snapshots become regression artifacts, not the primary contract) and [[snapshot-error-triage]] (assign each snapshot-embedded error an explicit role). Blocking/design-gated items ([[test-coverage-gaps]]): modal and dependent-argument suites are skipped pending modal-inference and dependent-checking work; the REPL tutorial runner stays skipped. Four expansion dimensions are planned but not started — [[fuzz-testing]], [[property-based-testing]], [[negative-testing]], [[integration-testing]] (executing emitted JS/C/Erlang, multi-module programs) — deferred until the core stabilizes. Next step: convert the snapshot-primary elaboration suites to direct semantic assertions and triage integration snapshot errors, which also gate `lowerToMir` retirement.

## Usage Semantics

Yap's quantity modality follows QTT ([[modal-type-theory]], Atkey 2018) and Idris 2: a {0, 1, ω} semiring of multiplicities carried in the shared `Modal` wrapper alongside the liquid-refinement dimension ([[modality-system]]). The semiring arithmetic is implemented and elaboration threads usage vectors through inference. Enforcement does not exist: the `MultiplicityMismatch` error is defined but never raised, no pass compares actual usage against declared grade, and inference strips modal wrappers so it sees clean structural types. This is by design — [[verification-modal-phase]] places quantity checking in the verification pass after full inference, unifying quantity and liquid checks rather than tangling usage accounting into bidirectional inference. The thread is therefore deferred pending that consumer, which gates downstream work: [[gram-crud-enrichment]] runs conservative CRUD defaults until enforcement lands, and principled [[type-erasure]] remains open. Two extensions are speculative: [[modality-polymorphism]] (grade metavariables, dependent on enforcement existing first) and [[effects-as-modality]] (effect indices as a third modal dimension). Next step: wire the post-elaboration usage pass that consumes the threaded vectors and raises `MultiplicityMismatch`.

## Verification Backend

The owned stack is in place: Yap emits obligations as solver-neutral IVL formulas and discharges them with an in-tree CDCL(T) engine — boolean search with clause learning over EUF (congruence closure), linear arithmetic (simplex), and trigger-based quantifier instantiation with bounded MBQI fallback. D-001 ([[z3-replacement.adr]]) is fully realized: the `z3-solver` dependency, Z3 adapter, and entire v1 solver path are gone, the active backend being the monadic one-shot v2 ([[solver-v2-monadic-port.implementation]]) with a small-step replay [[solver-trace]]. The current effort is D-009 ([[vc-validity-before-sat.adr]]), inserting a [[vc-validity-discharge]] layer that interprets a guarded VC as a proof obligation and queries for a counterexample (`assumptions ∧ ¬goal`), mapping `unsat`→`valid`, `sat`→`invalid`. This reframing recently resolved two long-standing discrepancies — [[block-scoped-let-vc-parity-bug]] and the [[solver-v2-universal-refinement-false-sat]] case (both 2026-06-21) — by separating the verifier verdict from raw satisfiability; residual divergence is now correctly scoped to general quantified-SMT completeness ([[quantifier-instantiation-boundary]]). The blocking item is finishing D-009: the PoC lives only in the integration helper and one refinement test, so CLI, explorer, and module-compilation verdict paths still treat raw solver output as user-facing and need the same validity-wrapper audit — the next step. A `:label` inside a refinement now translates to a VC — the sibling-label scope is re-established at every record boundary ([[verification-label-scope]], [[ivl-label-translation]]) — which surfaced a pre-existing false-valid discharge of symbolic record-field refinements ([[record-refinement-false-valid.bug]]), an instance of the same quantifier-instantiation boundary. Beyond it: string theory ([[milestone-3-strings]]), row theory ([[milestone-4-rows]], shared with Row Types), and UNSAT cores / models ([[milestone-5-explanations]]). Shift/reset stays a verification stub until Bubble semantics lands.
